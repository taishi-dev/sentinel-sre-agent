# Red CI Demonstration (Beat 3) + Baseline-Jump Closing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "Beat 3" to the recorded submission video — a live, genuine red `eval-gate` Continuous Integration (CI) run proving the gate fails on one unsafe autonomous action — plus the baseline-to-current root-cause-accuracy jump in the closing.

**Architecture:** The demonstration driver `deploy/record-take.sh` gains an opt-in Beat 3 section (guarded by an environment variable so existing rehearsals are unaffected) that pushes a throwaway git branch on camera and waits while the presenter watches CI turn red. The single scenario that trips the gate lives only on that throwaway branch, which is never merged; the driver and documentation changes are the only things merged to `develop`.

**Tech Stack:** Bash (`deploy/record-take.sh`), Python 3.12 evaluation harness (`src/sentinel/`), JSON scenario files (`scenarios/`), Markdown submission docs (`docs/submission/`), GitHub Actions (`.github/workflows/ci.yml`).

## Global Constraints

- **The scenario file must never reach `develop`.** `scenarios/11-destructive-migration-regression.json` exists only on the throwaway branch `V1-sentinel/exp-red-ci-demo`. If it merged to `develop`, the submission's own CI (`unit` and `eval-gate` jobs) would turn red. Every task that touches the scenario file happens on the throwaway branch only.
- **Throwaway branch name is exactly `V1-sentinel/exp-red-ci-demo`.** The `V1-sentinel/` prefix is required for CI to trigger (`.github/workflows/ci.yml` line 4: `branches: ["V1-sentinel/**"]`). The branch is deleted from the remote after recording and never merged.
- **Beat 3 in the driver is opt-in via `BEAT3=1`.** Default runs (rehearsals, `AUTO=1` validation, the current interactive take without the flag) must skip Beat 3 entirely so no accidental `git push` or remote-branch deletion occurs. This preserves the driver's existing behavior verified on 2026-07-04.
- **Total video length target rises to approximately four minutes thirty seconds.** The hackathon imposes no hard maximum (confirmed by the user on 2026-07-06).
- **Repository is `taishi-dev/sentinel-sre-agent`.** GitHub Actions Uniform Resource Locator (URL): `https://github.com/taishi-dev/sentinel-sre-agent/actions`.
- **Do not modify `src/sentinel/policy.py`, `src/sentinel/pipeline.py`, or any test file.** Option (a) accepts that the throwaway branch's `unit` jobs also fail; no test assertions are edited.

Between the closing `pause` (line 135) and the `# ---- cleanup` comment (line 137), insert:

```bash
# ---- Beat 3: prove the eval gate bites (opt-in via BEAT3=1) -----------------
if [ "${BEAT3:-}" = "1" ]; then
  cue "BEAT 3  ゲートは飾りではない — 危険な自律行動で CI を赤にする"
  say "Beat 3 の行を読みながらプッシュする"
  run git push origin "$DEMO_BRANCH"
  BEAT3_PUSHED=1
  printf '\nGitHub Actions を開く: %s\n' "$ACTIONS_URL"
  printf 'eval gate ジョブを開く（unit ジョブも赤になるが、狙いは eval gate）。\n'

  pause
fi
```

`BEAT3_PUSHED=1` is set only after the push succeeds, so both cleanup paths (abort trap in Step 2, normal cleanup in Step 4) attempt the remote-branch deletion only when this run actually pushed the branch.
