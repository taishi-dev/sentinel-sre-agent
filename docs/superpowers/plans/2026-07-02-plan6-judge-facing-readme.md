## Terms used in this plan

- **Sentinel agent** — the autonomous site reliability engineering program in `src/sentinel/` that receives a Cloud Monitoring alert, diagnoses a root cause, and either rolls back a Cloud Run revision or escalates to a human.
- **shop service** — the demonstration web service in `src/shop/` that the Sentinel agent monitors; the shop service has fault-injection endpoints for staging incidents.
- **judge-facing README** — the rewritten root `README.md`, aimed at a hackathon judge who opens the public repository `taishi-dev/sentinel-sre-agent` and decides in a few minutes whether the project is credible.
- **offline evaluation harness** — the program run by `python -m sentinel.eval_cli`, which scores a diagnoser against the ten labeled scenario files under `scenarios/` and prints a scorecard.
- **downgrade-only safety model** — the design property that the decision pipeline may only keep or reduce the autonomy of the action a diagnosis recommended, never increase the autonomy; implemented across `src/sentinel/policy.py` and `src/sentinel/pipeline.py`.
- **live trial** — the recorded result in `scorecards/v0.3.1-live-trial.md`: five autonomous rollbacks out of five staged live incidents against the deployed Sentinel agent.
- **Mermaid** — a text-to-diagram language that GitHub renders inside markdown files when the diagram source sits in a fenced code block labeled `mermaid`. External source: https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams
