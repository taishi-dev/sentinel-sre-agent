## 作品タイトル

Sentinel — 「動かない」を判断できる自律SREエージェント

## 概要（2〜3文）

Cloud Monitoring のアラートを起点に、ログとリビジョン履歴を自律調査し、Gemini で根本原因を診断して、安全なら Cloud Run のリビジョンを自動ロールバック、危険なら人間へエスカレーションする SRE エージェントです。価値の中心はロールバックの実行ではなく「いつ動いて、いつ動かないか」の判断にあり、その抑制はプロンプトではなく決定論的なポリシーゲート（コード）で強制されています。安全性は 10 シナリオの評価ハーネスで測定され、「危険な自律行動ゼロ」が CI のマージゲートになっています。

## ストーリー

### ① 本作品で解決したい課題とその背景

サービス障害の一次対応（オンコール）は、深夜のアラートに起こされ、眠い頭でログを漁り、直近のデプロイを疑ってロールバックを打つ——という消耗の激しい仕事です。一方で「アラートが来たら自動でロールバック」という素朴な自動化は危険です。障害の中には、ロールバックしてはいけないもの（セキュリティ修正を巻き戻してしまう、個人情報漏えいのように人間の判断・報告義務が必要、DB マイグレーションが絡み巻き戻すと悪化する等）が混ざっているからです。つまり本当の課題は「ロールバックの自動化」ではなく「**ロールバックして良いかどうかの判断の自動化**」であり、これは自律的に調査・判断・実行する AI エージェントでなければ解けません。「アラートが来たら無条件にロールバック」という自動化だけならエージェントは不要です。Sentinel が新しく提供するのは診断と、安全側に倒れる判断です。

### ② 想定する利用ユーザー

Cloud Run 上でサービスを運用しているが、専任の SRE ローテーションを組む余裕のない小規模チーム・スタートアップ・個人開発者。オンコール当番の「最初の 15 分」——調査・切り分け・定型復旧かエスカレーションかの判断——を Sentinel に委ね、人間はセンシティブな障害の対応に集中できます。

### ③ プロダクトの特徴

1. **二重ゲートの安全設計。** LLM の診断結果は、(a) 決定論的ポリシーゲート（`security_regression` / `pii_exposure` は確信度に関わらず自律行動を禁止。自律行動は `code_regression` / `transient_blip` / `runtime_mismatch` の許可リストのみ）、(b) 確信度ゲート（0.8 未満はエスカレーション）——の両方を通過しない限り実行されません。ゲートは行動を「格下げ」しかせず、診断の推奨より自律的な行動を選ぶことはできません（コードで強制）。
2. **安全性を「測定」する評価ハーネス。** 10 種類のラベル付き障害シナリオ（コード起因・依存先障害・設定ドリフト・セキュリティ・PII・リソース枯渇・DB マイグレーション・一過性・外観バグ・ランタイム不整合）で診断とアクションを採点。最新スコアは根本原因 10/10・アクション 10/10・危険な自律行動 0 件。この評価は GitHub Actions のマージゲートとして毎プッシュ実行され、危険な自律行動が 1 件でもあれば CI が落ちます。
3. **本番同等のライブ実証。** デプロイ済み環境での実地試験で、ステージした障害 5 回中 5 回の自律ロールバックに成功（2026-07-01 の試験ではリビジョン切り替えまで平均約 12 秒を計測、`scorecards/v0.3.1-live-trial.md`。動画収録時は環境条件により数十秒かかる場合があります）。PII 漏えい時にロールバックを**拒否**して Slack へエスカレーションする挙動は、オフライン評価（10/10）で検証済みであり、デモ動画の beat 2 でデプロイ済み環境上で実演しています。
4. **運用者体験（ユーザビリティ）。** インターフェースは使い慣れた Slack のみ——新しいダッシュボードを覚える必要がありません。通知は人間が数秒で判断できる定型フォーマット（サービス名・根本原因・確信度・理由・実行結果）で届き、エスカレーション時には「なぜ自律で動かなかったか」の理由がそのまま書かれています。再現も簡単で、デモは `deploy/demo.sh` の 1 コマンド、オフライン評価は クローン後 3 コマンド・5 分で誰でも実行できます（README 記載）。
5. **運用を見据えた実装。** 最小権限サービスアカウント・認証必須イングレス・Secret Manager によるシークレット管理・pyright strict / ruff / 104 テストの CI。ヘキサゴナルアーキテクチャで Google SDK 呼び出しをアダプタに隔離し、意思決定ロジックは完全にオフラインでテスト可能。
