# Live trial: v0.3.1-gemini — five staged incidents, five rollbacks

- **Date:** 2026-07-01
- **Code under test:** version 0.3.1 (decisive-prompt change, commit db2e80b), deployed to Google Cloud Run, with no Plan 5 changes
- **Completion bar:** five autonomous rollbacks out of five staged live incidents (Decision 4.A in `docs/superpowers/plans/2026-07-01-plan5-live-error-rate-signal.md`)
- **Result:** ROLLBACK CONFIRMED 5/5 — the serving revision of the shop service flipped from `shop-00002-jr8` to `shop-00001-7ls` within approximately 12 seconds in every round

## Procedure per round

1. Reset the Sentinel agent's Pub/Sub subscription (clear queued alerts).
2. Restore the shop service so one hundred percent of traffic serves from the latest revision.
3. Clear any existing fault, then inject the `checkout_error` fault into the shop service.
4. Generate server-error traffic: twelve requests to the `/checkout` endpoint, all twelve returning Hypertext Transfer Protocol status 500.
5. Publish the synthetic alert to the Sentinel agent's Pub/Sub topic.
6. Poll the shop service's serving revision until the revision changes (rollback observed) or a timeout elapses.
